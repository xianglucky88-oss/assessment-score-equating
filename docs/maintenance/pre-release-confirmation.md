# 发布前人工确认点

本清单在**每次**将变更用于正式成绩产出前人工执行并签字。它不假设任何自动化
存在——当前仓库没有 CI，以下每一步都是人工动作。

## A. 资产一致性

- [ ] `python3 tools/regen_contract_snapshots.py --check` 通过；若不通过，
      每处 diff 已在变更记录中逐条解释。
- [ ] `PYTHONPATH=src python3 -m unittest discover -s tests -v` 通过；
      同时已确认本次变更点不在现有测试覆盖范围内时的替代核对方式
      （规则目录第 5 节列出了测试实际固定的内容）。
- [ ] `docs/contract/` 三份文档与代码现状一致（抽查本次变更触及的条目）。

## B. 数据与归档

- [ ] 本次运行使用的输入载荷已原样归档（文件级快照，非"可重新导出"的承诺）。
- [ ] 代码版本（git commit）已记录并与载荷快照关联。
- [ ] 变更前基线输出已保存（用于回滚 diff）。
- [ ] 若涉及键修订或题目替换：变更前后的 `keys`/`void_items` 差异清单已随
      变更记录存档。

## C. 边界抽查（每次至少覆盖以下各项的一个实例）

- [ ] 一个舍入边界值（乘积第三位小数为 5）的 `scale`，手工复算并与输出核对
      （参照 case-04 的实际舍入行为）。
- [ ] 一个作废题考生的 `attempted`/`raw`，确认作废题未计入。
- [ ] 一个"全部作答被作废或无作答"的考生，确认其在输出中的处理方式符合
      当前契约（消失而非 0 分——除非契约已裁决变更）。
- [ ] 输出顶层键集合仍为 `project/scores/status/void_items`；若变更新增了
      字段，确认已按 L2 流程处理并公告下游。

## D. 沟通与登记

- [ ] 成绩使用方已收到口径变化说明（L1/L2 变更必须；L0 可免）。
- [ ] 变更记录状态更新为"已发布"，契约版本号已同步到 `docs/README.md` 与
      规则目录头部。
- [ ] 本次发布暴露的新歧义（如有）已追加到歧义案例集，状态为【未裁决】。
