# 变更记录（模板）

> 使用说明：复制本模板填写，一份变更一份记录，存入 `docs/maintenance/records/`
> （目录随首份记录创建）。文件命名：`CR-<YYYYMM>-<序号>-<简述>.md`。
> 所有"现状"描述必须与 `docs/contract/` 中的【已验证】内容一致；
> 计划中的行为写在"变更后"，不得写成既成事实。

- **变更编号**：CR-<YYYYMM>-<序号>
- **状态**：提议 / 评审中 / 已批准 / 已发布 / 已回滚
- **提案人 / 日期**：
- **契约版本**：当前 <x.y> → 变更后 <x'.y'>

## 1. 变更描述

- 类别（A/B/C/D/其他）与子情形：
- 动机（业务原因，非技术细节）：
- 变更前行为（引用规则目录条目或歧义用例编号）：
- 变更后行为（明确是代码变更、输入数据变更还是流程变更）：

## 2. 影响面

- 触及的输入字段 / 全局语义：
- 连带输出字段（依依赖速查表）：
- 受影响的 fixture 与快照（列出文件，含 `fixtures/input.json`）：
- 受影响的测试断言（逐条列出，或写"无，但已人工核对……"）：
- 兼容分级（L0/L1/L2）与理由：

## 3. 历史报告

- 需要重跑的场次范围（或不重跑的理由）：
- 重跑前后的口径差异说明（向成绩使用方公告的文本）：
- 归档位置（变更前载荷快照、代码版本、输出基线）：

## 4. 回滚方案

- 回滚步骤（对应兼容矩阵中该类别的步骤，逐条具体化）：
- 回滚校验方式（快照 diff、抽查清单）：
- 回滚的限制（如归档缺失时的声明）：

## 5. 评审与确认

- 评审清单（review-checklist.md）完成情况：
- 评审人 / 日期 / 结论：
- 发布前人工确认（pre-release-confirmation.md）完成情况：
- 裁决了哪些【未裁决】问题（同步更新 ambiguity-cases.md 的裁决记录）：
