# 变更评审清单

任何触及输入字段、输出字段、全局语义或代码的变更，评审人必须逐项作答。
回答"否"或"不适用"需写明理由。清单对应 `docs/contract/compatibility-matrix.md`
末尾的自查流程。

## 1. 变更定性

- [ ] 变更类别已确定（A 题目替换 / B 键修订 / C 缺考违规状态 / D 舍入 / 其他），
      并写明子情形（如 A3、B2）。
- [ ] 兼容分级已确定（L0 / L1 / L2），分级理由已记录。
- [ ] 是否触及全局语义（舍入、缺省量尺、缺省键、排序、作废时机、去重、未知字段
      策略、包络合并）？触及任一即 L2，不得降级。

## 2. 影响面追踪

- [ ] 已用依赖速查表列出所有连带输出字段（含 `void_items` 回显与 `scores`
      行集合变化，如考生消失）。
- [ ] 已列出 `fixtures/contract/` 中所有受影响用例，快照已再生成，
      diff 已逐条人工核对。
- [ ] 已确认 `fixtures/input.json` 与 `tests/test_core.py` 是否受影响；
      若测试断言不需要改，已说明"断言不变不代表行为不变"的核对过程。
- [ ] 已确认是否引入新的**静默行为**（缺省值、丢弃、忽略、类型漂移）；
      若是，已对照歧义案例集确认不与既有待裁决问题冲突。

## 3. 历史报告与重跑

- [ ] 已书面决定：哪些历史场次需要重跑，哪些不重跑及理由。
- [ ] 重跑所需的归档（变更前输入载荷快照 + 代码版本）已确认存在；
      不存在时已声明"回滚与审计不可验证"的限制。
- [ ] 若变更影响复核相关流程：已确认当前流水线**没有**复核环节，本次变更是
      新增还是纯外部流程调整，并已按契约新增处理。

## 4. 文档与资产同步

- [ ] 变更记录已按 `change-record-template.md` 填写。
- [ ] 契约版本号已按分级更新（L1→MINOR，L2→MAJOR）。
- [ ] 规则目录、兼容矩阵、歧义案例集中受影响的描述已同步修订；
      新暴露的歧义已追加到歧义案例集（含最小用例与快照）。
- [ ] `python3 tools/regen_contract_snapshots.py --check` 已运行并通过
      （或 diff 已逐条解释并记录在变更记录中）。

## 5. 禁止事项（任一命中即退回）

- [ ] 不得把【建议】或【未裁决】内容当作既有契约事实写入文档或代码注释。
- [ ] 不得在未归档变更前载荷快照的情况下执行会改变历史输出的重跑。
- [ ] 不得只改输入数据（如在作答行加 `status`）而不评估引擎是否真的会读取
      （参照 case-08 陷阱）。
- [ ] 不得以"测试通过"作为行为未变的唯一证据——当前测试只固定少量断言
      （规则目录第 5 节）。
