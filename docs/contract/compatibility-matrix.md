# 变更兼容矩阵与回滚步骤

本文档回答变更评审的核心问题：**一次修改会影响哪些 fixture、哪些输出字段、
哪些历史报告，以及如何回滚。** 配合 `rules-catalog.md` 的依赖表使用。

## 0. 兼容分级

| 级别 | 定义 | 契约版本影响【建议】 |
|---|---|---|
| **L0 兼容** | 输出 schema 与所有输出值均不变（如纯文档、注释变更） | 不变 |
| **L1 值变更** | 输出 schema 不变，部分 `(student, form)` 行的值变化 | MINOR +1 |
| **L2 破坏性** | 输出 schema 变化（增删字段、改类型、改排序），或全局语义变化（舍入、缺省值、作废时机、去重） | MAJOR +1 |

依赖速查（输入字段 → 派生链 → 输出字段，均【已验证】，详见规则目录第 2 节）：

| 变更的输入 | 直接影响的 | 连带影响的输出字段 |
|---|---|---|
| `responses[].answer` | 判等计分 | `raw` → `scale` |
| `responses[].item` | 作废判定、键查找 | `attempted`、`raw`、`scale` |
| `responses[].student/form` | 分组与排序 | `scores` 行集合与顺序 |
| `keys[item]` | 判等计分 | `raw` → `scale` |
| `void_items` | 作废过滤 | `attempted`、`raw`、`scale`、`void_items` 回显、`scores` 行集合（考生可能消失） |
| `scale[form]` | 量尺乘数 | `scale` |
| 代码全局语义 | 舍入/缺省/排序/去重 | 可能波及**所有**输出字段 |

## A. 题目替换（item replacement）

| 子情形 | 分级 | 输出字段影响 | fixture/快照影响 | 历史报告影响 |
|---|---|---|---|---|
| A1 新增题目（新 item + 键 + 作答行） | L1 | 涉及考生的 `attempted`/`raw`/`scale` | 新增或更新含该题的输入与快照 | 仅当用新载荷重跑旧场次时变化 |
| A2 题目退役、新题上岗（换 ID） | L1（面向未来场次） | 同上 | 同上 | **编辑历史载荷属程序性破坏**：历史载荷一旦改动，原报告不可复现 |
| A3 作废题目（加入 `void_items`） | L1 | 该题所有作答行退出 `attempted`/`raw`；`void_items` 回显变；只剩作废题的考生**从 `scores` 消失**（case-01） | 涉及作废题的用例（case-01、case-09） | 同上；重跑范围必须书面化 |
| A4 从 `keys` 删题但保留作答行 | L1（**隐性**） | 该题作答变为不得分——**除非**作答为 `null`，此时反而得分（case-02）；无任何报错 | case-02 | 极易被误判为"无影响"，审查必须显式拦截 |

**回滚步骤（A 类通用）**
1. 确认归档：找到变更前的输入载荷快照与代码版本（git commit）。**归档缺失则回滚无法验证，只能声明限制。**
2. 冻结当前输出：用当前载荷重跑并保存 stdout，作为回滚前基线。
3. 恢复：还原 `responses`/`keys`/`void_items` 中被改动的条目（A3 还需还原作废表）。
4. 重跑受影响的 `(student, form)` 范围（通常是整个场次，因为排序与行集合可能变）。
5. 校验：与第 1 步归档的输出逐字节 diff；`fixtures/contract` 相关快照运行 `tools/regen_contract_snapshots.py --check`。
6. 登记：在变更记录中写明回滚原因、范围、校验结果。

## B. 评分键修订（key revision）

| 子情形 | 分级 | 输出字段影响 | fixture/快照影响 | 历史报告影响 |
|---|---|---|---|---|
| B1 修改既有键值（如 `Q1: A→C`） | L1 | 作答等于旧/新键的考生行 `raw`/`scale`；`attempted` 不变 | case-07a/07b | **输出不含键版本**，重跑即无痕覆盖（case-07）；必须配变更记录 + 载荷快照归档 |
| B2 键改为 `null` | L1（隐性） | 作答为 `null` 的考生变为得分；其余不变 | case-02 | 同上 |
| B3 删除键 | L1（隐性） | 该题作答与 `None` 比较：具体作答不得分，`null` 作答得分 | case-02 | 同上 |

注意 B2 与 B3 **不等价**：`"Q1": null` 是显式键，`keys` 中无 `Q1` 是缺省比较，
两者在当前代码下行为一致（都与 `None` 判等），但语义意图不同，变更记录中必须
写明是哪一种。【已验证：engine.py:5】

**回滚步骤（B 类）**
1.–2. 同 A 类。
3. 恢复 `keys` 中被修订的条目到变更前值。
4. 重跑受影响场次（键修订影响面 = 所有作答过该题的考生，跨 form）。
5.–6. 同 A 类。校验时重点 diff `raw` 与 `scale` 两列。

## C. 缺考 / 违规状态（absence / misconduct）

**现状（【已验证】，必须先读再改）：** 契约没有 `status` 字段。作答行里写入
`"status": "absent"` 会被引擎**静默忽略**，成绩照常计算（case-08）。缺考的
隐式表示是"该生无作答行"，结果是该生**从 `scores` 消失**而非得到 0 分
（case-01 同款机制）。违规无任何表示。

| 子情形 | 分级 | 输出字段影响 | fixture/快照影响 | 历史报告影响 |
|---|---|---|---|---|
| C1 仅在输入中加 `status` 字段、不改引擎 | L0（技术上）/ **语义陷阱** | 无 | case-08 | 无；但下游若误以为生效即产生错误决定，审查必须拦截 |
| C2 引入 status 语义（引擎改动 + 新输出字段） | **L2** | 新增输出字段；`scores` 行集合可能变（缺考生是否出现？） | 全部 status 相关用例新增 | 新旧报告口径不同，必须分段说明 |

C2 在评审前必须裁决的问题（当前均【未裁决】，裁决结果写入契约）：
- 缺考考生是否出现在 `$scores` 中？若出现，`attempted`/`raw`/`scale` 取什么值？
- 违规是作废该生全部作答（类似 void），还是仅打标记保留计分？
- 状态附着在行（response）还是考生-表单（student, form）粒度？当前引擎只读
  行级字段，行级状态互相冲突（同一生同一 form 两行不同状态）时如何处理？

**回滚步骤（C 类）**
- C1：删除输入中的 `status` 字段即可，输出不变。
- C2：属代码变更——恢复上一代码版本，重跑受影响场次，按 A 类第 5–6 步校验与登记；
  已按新口径发布的报告需作废声明，不能静默替换。

## D. 舍入规则变化（rounding）

**现状（【已验证】）：** `round(raw * scale, 2)` = Python 银行家舍入
（half-even）作用于二进制浮点。`1.125→1.12`、`2.675→2.67`、`1.005→1.0`
（case-04）。整数量尺乘数产生整型输出（`10`），浮点乘数产生浮点输出
（`10.0` / `1.0`），JSON 文本表示不同（case-10）。

| 子情形 | 分级 | 输出字段影响 | fixture/快照影响 | 历史报告影响 |
|---|---|---|---|---|
| D1 改舍入模式（如 half-up）或改 Decimal | **L2** | 所有命中边界值的 `scale` | 所有含非整数乘积的快照（至少 case-04、case-10） | 边界点新旧不可比；必须公告断点 |
| D2 改输出精度（如 2 位 → 3 位） | **L2** | 全部 `scale` | 全部含 `scale` 的快照 | 同上 |
| D3 统一量尺乘数类型（int/float） | L1（文本表示变） | `scale` 的 JSON 文本（`10`→`10.0`） | case-10 及所有整数乘数用例 | 数值不变、文本变；按值消费的下游无感，按文本 diff 的流程会报警 |

**回滚步骤（D 类）**
1.–2. 同 A 类（D 类是代码变更，归档必须含代码版本）。
3. 恢复上一代码版本（`engine.py` 的舍入表达式）。
4. 重跑**全部**受影响场次——舍入是全局语义，影响面不能用考生子集界定。
5. 校验：除快照 diff 外，人工抽查边界值（`*.x25`、`*.x75`、第三位小数为 5 的乘积）。
6. 登记，并标注新旧口径断点日期。

## 变更影响自查（评审时逐行填写）

1. 改了哪个输入字段或哪条全局语义？→ 查第 0 节依赖速查，列出所有连带输出字段。
2. `fixtures/contract/` 中哪些用例覆盖这些字段？→ 这些快照必须再生成并人工核对 diff。
3. `fixtures/input.json` 与 `tests/test_core.py` 是否受影响？→ 测试只固定
   `scores[0].raw == 1` 等少量断言（规则目录第 5 节），断言不变不代表行为不变。
4. 历史报告是否需要重跑？→ 写出场次范围与不重跑的理由，二者必居其一。
5. 回滚前置条件（载荷快照 + 代码版本归档）是否已满足？
